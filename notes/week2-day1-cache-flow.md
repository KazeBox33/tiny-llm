# 第二周第一天：接通缓存与生成流程

本次对应新版教材任务二至任务四中的模型状态传递、请求独立缓存和生成循环。
保留现有的量化投影实现，因此这里的结果验证调用正确性，尚不能作为仅改变缓存算法的性能对比。

## 数据流

1. 生成函数调用 `model.create_kv_cache()`，为本次请求的每层创建独立缓存。
2. 第一次输入完整提示词，位置偏移为零，各层分别保存自己的 K/V，也就是注意力使用的键和值。
3. 后续每次只输入上一轮生成的词元；位置偏移等于此前已经缓存的词元数量。
4. 注意力层先对新 Q/K 应用旋转位置编码，再把新 K/V 加入缓存。
5. 新查询读取完整历史 K/V，得到新位置的输出；历史词元不重新经过各层。
6. 收到结束词元或达到输出上限时结束，并输出文本解码器缓冲区中的剩余内容。

提示词长六、随后解码一个词元时，每层缓存长度从六变成七。
模型在进入任何一层前检查缓存数量和位置一致性；错误的位置会触发异常，缓存不被修改。

## 本次改动

- `Qwen3ModelWeek2.create_kv_cache` 为每次调用创建独立的各层缓存。
- 模型入口检查各层缓存数量和位置偏移，避免漏算模型层或使用错误位置编码。
- 带缓存的生成函数使用模型的缓存创建入口，默认最多生成 256 个新词元，拒绝空输入和非法输出上限。
- 生成结束时调用文本解码器的 `finalize`，输出尚未显示的文本。

## 2026-10-26 验证

```bash
pdm run python -m pytest tests/test_week_2_model.py tests/test_week_2_cache.py -q
pdm run python -m pytest tests/test_week_2_generation.py tests/test_week_1_completion.py -q
```

分别得到 8 项和 27 项通过。两层小模型使用 128 维隐藏状态、4 个查询头、2 个键值头、32 维注意力头、四位权重和 BF16 激活值。
整段六个词元、逐词元、分成 3/1/2 个词元三种方式与 MLX-LM 整段计算的输出比较通过，绝对和相对容差均为 0.05。
另外验证了各层及各请求的缓存隔离、错误位置时不改变缓存、生成输入长度和位置、输出上限及文本收尾。

原课程 Qwen3-4B 测试结果为：预填充分数对照失败，逐词元对照通过。
Qwen3-0.6B 的两项对照因本地没有对应权重而跳过，未下载新模型。
旧测试脚本没有透传 `pytest.main` 的返回码，因此上述结果以测试报告为准，不能根据脚本退出码零判断全部通过。

为检查失败是否由本次改动引入，使用改动前的 `e5f8054` 模型代码与当前代码，分别输入固定种子生成的十个词元。
两版使用相同的 Qwen3-4B 权重，输出逐元素完全相同，最大差异为零。
沿用原测试的归一化方式、绝对容差 1.0 和相对容差 0.1，与 MLX-LM 对照如下：

| 随机种子 | 修改前后最大差异 | 超出参考容差的元素数 | 与参考的最大差异 |
|---|---:|---:|---:|
| 0 | 0 | 0 | 1.75 |
| 1 | 0 | 664 | 4.0 |
| 7 | 0 | 17 | 3.75 |

这说明这些输入上的预填充误差在旧实现中已经存在，具体算子根因尚未定位；没有放宽测试容差。
缓存调用流程已验证，仍需单独解决这项数值差异，才能把真实 4B 预填充对照视为通过。

最后离线运行 Qwen3-4B，经过聊天模板处理后调用带缓存的生成函数，输出上限为 24 个新词元。
模型实际输出中文，函数在上限处正常返回。此项只验证完整运行流程，不构成回答质量或性能结论。
